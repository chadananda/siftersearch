# One hardware-adaptive worker image (design note, 10-28; build waits for the ASR benchmark)

1. **One entrypoint `sifter-worker`**, one codebase. At start it probes: NVIDIA (`/dev/nvidia*`, nvidia-smi), AMD (`/dev/kfd`, sysfs: VRAM / GTT / system RAM as separate pools), else CPU (cores, AVX, RAM). It picks an engine per stage from a table keyed by hardware (ASR: faster-whisper CUDA | the boss benchmark winner on ROCm | CPU int8; UniPASE: torch CUDA | ROCm; diarization, langid, alignment likewise) and never crashes on a missing GPU.
2. **Self-calibration**: first start runs a 30-60 s bundled clip, records RTF per stage and VRAM/RAM per stream, caches it, and reports `{gpu_vendor, gpu_name, vram_gb, gtt_gb, ram_gb, cores, engines[], measured_rtf{stage}, max_concurrency}` to tower. Tower routes orders by capability and measured speed (this replaces "only aorus takes whole orders": any host reporting an ASR engine may).
3. **Concurrency** = the live feedback controller (`scripts/media/worker/controller.py`) fed by the two-pool probe (PSI, MemAvailable, VRAM free, GTT); per-job memory caps via `capped.sh` / `--memory` (cgroups do not cap VRAM: job count x per-job need does).
4. **Job source is a driver, chosen by env**: `JOB_SOURCE=tower` (default; aorus and boss, LAN, no R2, no credentials) or `JOB_SOURCE=tower-assign+http` (rented pods). Same code, same image.
5. **Pods: inputs over plain HTTPS** from the content-addressed prefix `inputs/<sha256>/<name>` (R2 custom domain / r2.dev, listing off, range + parallel GET, lifecycle delete a few days after tower acknowledges). No presigning, no token, no R2 credential in the pod. Data is not secret; keys (RunPod, Gemini, ElevenLabs, R2 write, internal) never go to pods.
6. **Tower assigns, pods process, tower pulls**: the work order (ssh/HTTP with a shared-secret token or key, so strangers cannot use our compute or inject results) names the input URL; outputs stay on the pod and tower pulls each finished talk (web copies, transcript, verdict) while the next one runs; tower validates the manifest, acknowledges, then the pod may delete it.
7. **No loss when tower is away** (reboot, UPS read-only): the dead-man switch and the reaper hold off while un-acknowledged results exist, for up to 30 min after the last output; the controller logs a loss only after that grace.
8. **Rent controller = work first, rent second**: rent only when pending inputs already sitting in R2 total >= N audio-hours; scale pods to the queue; terminate when pending is empty (existing dead-man switch and reaper stay). Tower's background uploader (resumable multipart, parallel, niced, hash-verified, ordered by queue priority) fills R2 in free time, off the GPU clock.
9. **Packaging**: one Dockerfile, multi-stage targets with shared layers: `:cuda` (RunPod, aorus), `:rocm` (boss), `:cpu`, optional `:all` (both stacks, separate venvs, same entrypoint). Weights in shared layers; no secrets; public on GHCR via the GitHub Action; tag by version. Measure compressed size and cold pull per tag (the 64 GB single image made pod starts slow and failing; the pytorch-runtime base already cut it to ~38 GB uncompressed). Default: `:cuda` for pods.
10. **Tests**: selftest extended with the hardware probe + manifest; a pod with no write credentials finishes a talk end-to-end with tower pulling talk 1 while talk 2 still runs; tower down for 10 min loses nothing; capability manifest from aorus (Docker + NVIDIA toolkit) and boss (`--device /dev/kfd --device /dev/dri`); then a canary pod before any rental.
11. **Order of work**: (a) ASR engine benchmark on boss (whisper.cpp Vulkan/HIP, torch ROCm, Parakeet via ONNX, faster-whisper CPU baseline; 5 reference talks; WER vs corrected text, RTF, word-timing after alignment, memory per stream) -> (b) `:rocm` target with the winner -> (c) `:cuda` / `:cpu` targets + probe + calibration -> (d) the HTTP-input driver and tower-pull protocol -> (e) canary.

Baselines already measured (tools.js, 10-21/22): boss CPU Whisper turbo RTF ~0.07 aggregate over 4 jobs (14.4 audio-min per wall-min); aorus CUDA RTF ~0.038 for one job (26.6 audio-min per wall-min). A boss ROCm path must beat ~0.07 aggregate at equal accuracy to be worth building.

## Update 10-28 (late): decisions after the ASR benchmark and Chad's directives

**Benchmark (boss, gfx1151, 5 x 600 s reference clips, WER vs the corrected transcript.json; `scripts/media/asr-bench/`).** CPU rows ran while boss CPU was saturated by other jobs, so their RTF is pessimistic; GPU rows shared the GPU with UniPASE.

| engine | WER % (clean / muffled / noisy / fa) | RTF | memory per stream |
|---|---|---|---|
| **whisper.cpp HIP, large-v3-turbo** | 5.2 / 2.7 / 4.8 / 8.3 | **0.037-0.050** (0.023 alone) | 450 MB RSS, ~2.7 GB VRAM |
| faster-whisper CPU int8 turbo | 7.0 / 4.1 / 6.2 / 7.5 | 0.12-0.14 (loaded box) | 1.7 GB RSS |
| torch ROCm HF Whisper turbo / v3, fp16, 30 s windows | 7.7 / 3.4 / 7.1 / 45 ; 6.9 / 3.4 / 9.1 / 42 | 0.06-0.09 / 0.14-0.21 | 2.6 GB / 4.2 GB RSS; token timestamps blew RAM (17 GB), so unused |
| Parakeet v3 int8 via sherpa-onnx (CPU) | 16 / 19 / 60 | 0.065-0.078 | 1.9 GB; no Persian; rejected on WER |

The "interp" clip (Persian + English interpreter) is a language-routing test, not an engine test (all engines 60-90 %: one language per file). Vulkan was not tried (no Vulkan headers on boss); Canary/Moonshine not sized. **Winner: whisper.cpp HIP** - WER at or below the CPU baseline, 3-5x faster, and it is the same speed as aorus CUDA (0.038). Word timing: whisper.cpp token times are heuristic (median 166-377 ms vs the aligned reference), so the wav2vec2 forced alignment stays; it runs on ROCm torch (works). Alignment (whisperx CTC) is now the slow stage on boss: 230 s per 600 s of audio under load, ASR 30 s.

**Design changes (Chad's directives of 10-28):**
- **No CPU fallback for GPU stages** (ASR/transcribe, langid, realign, UniPASE, diarize where a GPU build exists, dfn, grade). CPU-suited stages (probe, metrics, waveform, encodes, packaging, word guard, uploads) stay on the CPU. Known exceptions, stated not hidden: sherpa-onnx has no ROCm build, so diarization runs on the CPU provider on AMD hosts; DeepFilterNet keeps its own CPU torch in both images.
- **Host admission** (`scripts/media/worker/capabilities.py`): a host needs a GPU (NVIDIA or AMD) PROVEN by a tiny run (torch matmul on the accelerator; on AMD also whisper.cpp language detection whose log must name the GPU backend; utilisation sampled), VRAM >= 8 GB, system RAM >= 16 GB, >= 4 CPUs, a working ffmpeg. Otherwise it prints the reason, exits 3, writes no claim, and a rented pod ends itself (`runpod_worker.main`). Minimums via `SIFTER_MIN_RAM_GB/VRAM_GB/CPUS`. The manifest (`engines`, `gpu_busy_pct`, `cpu_busy_pct`, VRAM, RAM) is written to `<spool>/.capabilities.json`; the controller heartbeat carries per-host GPU-busy % and CPU-busy % (NVIDIA via nvidia-smi, AMD via amdgpu sysfs). Test: `tests/api/media-capabilities.test.js`. The first real `:rocm` container run refused to start three times on missing pieces (no torch on PATH, libatomic, wrong ROCm userspace), which is the behaviour wanted.
- **One worker, N whole jobs in flight, no GPU/CPU lane split.** A whole job runs every stage in order on one host, each stage on the hardware it suits; concurrency comes from the live controller (VRAM, RAM/PSI, GPU util, thermals), not partitioned queues. Boss currently admits ONE whole container at a time (10 GB cap, MemAvailable >= 10 + 13 GB reserve) until the two-pool monitor shows what two jobs cost.
- **One host per order; audio is uploaded once** (upload is the bottleneck). `homeEligibleItem` (media-jobs.js) never offers an order another host holds; a retry reuses the host's checkpoints (job identity = id + input sha); an order moves only when the host is confirmed down. Test: `tests/api/media-whole-dispatch.test.js`.
- **Vendor-blind dispatch.** No aorus-first preference: boss takes `whole` orders when `boss_whole` is set in `media-worker-accepted.json` (set only after a proven end-to-end order), aorus takes them as before; a free host pulls the next order. Ranking by measured throughput (EWMA audio-seconds per wall-second per host from completed orders) is the next step; until it exists the faster-to-free host wins, which is the same thing on a loaded queue.
- **Packaging.** `:rocm` = `docker/media-worker/Dockerfile.rocm` (python 3.11-slim, AMD TheRock gfx1151 torch wheels, whisper.cpp HIP built on a ROCm image that MATCHES the host userspace - a 7.0 build segfaulted in libhsa against boss's 7.2.4 stack - and every data asset copied from the accepted CUDA image so there is one source of weights). Built on a host that holds the CUDA image (`whole-worker/build-rocm.sh`), 14.7 GB. The same Python/JS code serves both images; the engine is chosen at run time (`asr_engine()`: whisper.cpp on a host with `/dev/kfd` + the binary, faster-whisper CUDA otherwise; `runpod_worker.new_asr`). A single multi-arch tag cannot select by GPU vendor, so the tag family is `:cuda` (existing) and `:rocm`; the entrypoint, manifest and self-test are shared.
