# Meilisearch dependency map → retirement checklist (2026-10-04)

Order (Chad 10-04): everything in Qdrant + beat Meili on the batteries → retire Meili → only then concept extraction / new HyPE.
Generated by a read-only code sweep; file:line references as of commit 38085e67.

I mapped every Meilisearch dependency in the repo (`api/`, `src/`, `scripts/`, ops config); the map is below. Three things matter most for planning:

- **The live writer is `api/workers/unified-worker.js`**, run by PM2 as `siftersearch-worker` (`ecosystem.config.cjs:112`). `api/workers/sync-processor.js` is not in the ecosystem config and only tests reference it, so it is dead.
- **Even the existing Qdrant-only mode still depends on Meili.** With `meili:false` (`SEARCH_QDRANT=only`), the Qdrant hits are stubs and their paragraph bodies are still fetched with Meili `getDocuments({ids})` (`api/lib/search.js:1386-1401`).
- **The grounding pipeline's done-check uses Meili.** A book only counts as "searchable" if Meili hit counts come back non-zero (`api/lib/rag-adapter/store.js:491-519`).

## 6. What Qdrant/SQLite must provide

1. **Hybrid dense+BM25 search with a tunable blend** (`semanticRatio`, including 0 and 1) — `search.js:815`.
2. **Exact-phrase matching for quoted queries** — `source-resolve.js:122`, `chat.js:528`.
3. **Filters**: equality, `IN`/`NOT IN`, numeric ranges, and case-insensitive, apostrophe-agnostic substring matching on author/collection/title — `search.js:746-765`. The Qdrant layers currently use `author_fold` equality instead (`qdrant-layers.js` `toQdrantFilter`).
4. **Many sub-queries per request, merged afterwards** (per-religion fan-out, OL supplement, federation) — `search.js:281,1562`.
5. **A normalized relevance score per hit**, used by the authority re-ranking and the 0.55 relevance floor — `search.js:123,390`.
6. **Match positions for sentence excerpts and `<mark>` highlighting** (`_matchesPosition`, `_formatted`) — `highlighting.js:18`, `search.js:395`.
7. **Paragraph bodies fetched by id** — `search.js:1390`. SQLite should take this over.
8. **All paragraphs of a document in order** (filter `doc_id`, sort `paragraph_index`) — `audio.js:118`. SQLite already holds this.
9. **Fuzzy title/author document search** — `chat.js:1021`, `public-api.js:989`. `doc_meta_fts` is a model for this.
10. **Sorted retrieval by entity id** — `entity.js:31`.
11. **Hit counts per document or query** — `store.js:501`, `search-target.js:95`.
12. **Pure vector k-NN from a caller-supplied vector**, 512-dim OpenAI geometry; note the Qdrant layers use Gemini at 3072 dims — `admin.js:2308`.
13. **Alias synonym expansion** — `graph-meili-sync.js:87`.
14. **Separate site-only corpora / scope routing** — `scope.js:65`, `unified-worker.js:691`.
15. **Incremental upserts and deletes driven by the SQLite dirty flags** (`synced`, `enhanced_synced`, `em_synced`), with confirmation and reconciliation — `unified-worker.js:268,112`.
16. **Ops replacements**: health checks, queue/stats probes, backups and the systemd unit — `health-check.mjs:140`, `backup.js:95`.
17. **Frontend response shape**: `_formatted.text` and `<mark>` markup, or a frontend change — `ChatInterface.svelte:2557`.
