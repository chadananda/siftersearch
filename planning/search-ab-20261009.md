## Blockers to retiring Meili (beyond the scores)
1. **Hydration** — Qdrant hits were filled from Meili by id (`getDocuments`). FIXED 10-09 (pending deploy after the run):
   `api/lib/paragraphs-repo.js` — one `paragraphDoc()` used by the sync worker AND `paragraphsByIds()` (SQLite); Meili only
   for ids SQLite lacks (site-only stores).
2. Meili-only features still to move or replace: cross-tradition balancing, year/collection/title filters, highlighting
   (`_formatted`), quick search + library search, per-site indexes (balib/ool), stats endpoints.
3. Source preference / authority blend — Meili's ranking holds the original above books that quote it; Qdrant's phrase
   layer scores every copy equally (10-04 RRF sweep).
4. p95 tail (~13 s on every arm, 10-04) — shared, not Qdrant. 10-09 it is WORSE: Meili arm p50 3.1 s, p95 24.7 s, 24/516
   quality fixtures hit the battery's 25 s timeout → that run is INVALID by the script's own rule (errors void, not fail).
5. **Supplemental points carry no religion.** 8.69M of 31.16M phrase points (1.34M of 5.95M keyword points) are the scraped
   sites (`scope: supplemental`, bahai-library.com etc.) with `religion: null` — because `docs.religion` is NULL for those
   docs in SQLite (e.g. doc 28893 "God's Heroes", bahai-library.com). A Bahá’í-filtered Qdrant search therefore never sees
   them, while Meili keeps them in un-filtered per-site indexes (balib/ool). Fix at the source: set docs.religion for the
   site docs (site config knows its tradition), then set_payload religion on their points.
   (Correction: the earlier "24M non-Bahá’í phrase points" counted these as non-Bahá’í.)
